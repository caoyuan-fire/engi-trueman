# 行为效果验证

写作时，调查材料、局部正确性和作者自己的解释可能占据注意力；评阅成稿时，任务目的与阅读感受更容易成为判断依据。收到“不够好”的评价也可能让评阅者偏向找错。把这些作为需要验证的工作假设，不据此断言某个模型的具体训练成因。

本技能采用的改进是让执行者主动转换评估任务：从完成自己的工作，转到使用接收者真正拿到的结果。原有判断标准继续起作用，重点检验这个转换能否改善实际产物。

## 使用真实任务验证

选有明确用途的任务，给执行者原始需求、必要约束和原始材料。技能版本是这次试验的输入。产物写入独立临时目录，不改动来源工程、其他对话或线上系统。不要提供已有答案、对旧产物的批评或期待的改法。

有独立上下文且宿主允许时，使用独立执行者生成产物，再安排另一位独立使用者尝试使用。这是技能变更的前向验证；验证由当前 Agent 协调，参与者只处理分配的任务，不继续委托。

使用者接收相同的原始需求、必要材料和待用产物。请它按照需求完成一个具体的理解、决策、调用或维护动作，指出能从产物得到的依据与真正卡住的位置。允许反馈“可以直接使用”，不要预设必须找出缺陷，也不要用“找叠甲”“清除论文味”等结论提示它。

比较两个版本时，隐去版本、作者和先前评价，随机分配代号。先分别尝试使用，再比较适用程度。长度、限定语数量或标题数量都不能单独决定好坏；必要条件缺失、事实错误和关键能力丢失同样属于退步。

把反馈交给执行者修改时，保留具体观察与原始任务，不替它指定措辞。查看最终产物实际发生了什么变化。已经合适的内容应能保留，修改无需扩展到反馈无关的地方。

## 覆盖不同的取舍

- 文档任务：读者能否凭成稿理解分工、完成接入或作出选择；材料里的细节是否围绕这个用途组织。
- 工程任务：沿实际调用执行或检查改动；内部已有保证是否被利用，外部边界和高后果失败是否仍得到合适处理。
- 调查与答复：用户能否据此判断下一步；关键未知是否具体，证据不足时是否仍如实表达。

已有反例可以用于回归，另选未给出改写答案的任务检查迁移效果。发现失败后，先看执行者是否真的改变了评估任务、使用了最终产物，再决定怎样修订；避免为每个坏句子累加一条永久规则。

## 报告实际证据

区分结构检查、开关测试、同上下文自审、独立使用尝试和用户反馈。报告实际做过的验证、观察到的变化和未解决的问题。单次使用尝试可以支持下一次修订，不能代表所有任务上的稳定改善。
